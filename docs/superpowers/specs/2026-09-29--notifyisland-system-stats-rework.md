# NotifyIsland — System Stats rework (1.12.1)

Переделка визуала и поведения System Monitor после фидбэка на 1.12.0.

## Проблема

На скриншоте 1.12.0 пилюля в SystemStats выглядит как «широкая и обрезанная полоса»:
- метрики — голые `TextBlock` 11px без цвета, единиц, иконок;
- сеть рендерится как `v0,0` — литеральный символ `v` (вместо стрелки ↓) и делитель MB/s без суффикса;
- ряд метрик вставлен первым в `CollapsedRow`, но ширина пилюли в Idle остаётся 170px → переполнение;
- по клику ширина скачет 170 → 394px, высота остаётся 30px, и 4 строки расширенного вида обрезаются.

Клики реагируют неадекватно:
1. hit-test только по X (`OverlayWindow.axaml.cs:572-577`) — вся вертикальная полоса метрик кликабельна как «открыть статистику», включая зону часов рядом;
2. открыть = клик по метрикам, закрыть = клик где угодно (`:592-600`), в том числе по тексту, который читают;
3. двойной клик по метрикам → первый открывает SystemStats, второй сворачивает — моргание вместо Action Center;
4. автосворачивание по wall-clock 30 с (`OverlayMachine.cs:311-318`), не реагирует на чтение и наведение;
5. `PlayClickPop` подключён только к media prev/next (`:1502,1509`) — на пилюлю отклика нет.

## Решение (согласовано с пользователем)

| Вопрос | Решение |
|---|---|
| Где метрики | Отдельный слот. Idle = только часы. Метрики — свой экран, вход по наведению |
| Клик в Idle | Одиночный клик = пин/анпин (главное действие). Метрики не перехватывают клик |
| Расширенный вид | Переменная высота пилюли для SystemStats: 30 → 72 DIP |
| Стиль метрик | Только значения, приглушённый цвет, акцент на проблемных метриках |

### Как разрешается конфликт «отдельный слот» + «клик = пин»

В Idle метрик нет, значит «зоны метрик» не существует. Вход в SystemStats — **только по наведению** (`HoverExpandDelayMs = 250 мс`). Клик в Idle остаётся чисто пин/анпин, двойной клик — Action Center, зоны ⅓/⅓/⅓ буфера обмена не тронуты. Это ровно то, что выбрано в обоих пунктах, без взаимного противоречия.

## Целевое поведение

### Idle (30 DIP, ~170 DIP)
```
┌──────────────────────┐
│  12:34  вт 28 сент   │   ← часы + дата, как сейчас
└──────────────────────┘
```
- одиночный клик → пин/анпин
- двойной клик → Action Center
- наведение (250 мс) → SystemStats
- уход курсора (grace 500 мс) → обратно в Idle
- метрик в Idle нет вообще

### SystemStats (72 DIP, ширина ~300 DIP)
```
┌────────────────────────────────┐
│  CPU           12 %           │
│  Память        21,3 / 34 ГБ   │
│  Батарея       100 %           │
│  Сеть          ↓ 0,0 МБ/с ↑ 0  │
│  вт, 28 сентября 2026          │   ← полная дата, была в hover-peek
└────────────────────────────────┘
```
- значение справа, цвет `#C8C8CC` в норме;
- акцент `#3D9CF0` при переходе порога предупреждения, `#E8A0A0` при критическом пороге;
- вход/выход по наведению, авто-сворачивание по уходу курсора, wall-clock 30 с убрать;
- клик внутри SystemStats ничего не делает (только ПКМ → контекстное меню).

## Пороги акцента

| Метрика | Внимание | Критично |
|---|---|---|
| CPU | ≥ 70 % | ≥ 90 % |
| RAM | ≥ 85 % от total | ≥ 95 % |
| Батарея | ≤ 20 % | ≤ 10 % |
| Сеть | — (всегда норма) | — |

## Форматирование сети

Убрать литеральный `v`. Формат: `↓ {F1} МБ/с  ↑ {F0} КБ/с`, порог переключения единицы на 1024. При нуле показывать `↓ 0,0 МБ/с` без глифа направления-буквы.

## Что удаляется

- `SystemStatsPanel` из `CollapsedRow` (inline-метрики в Idle) — `OverlayWindow.axaml:35-44`
- X-only hit-test, открывающий SystemStats по клику — `OverlayWindow.axaml.cs:572-589`
- безусловный `Collapse` по любому клику при `Kind == SystemStats` — `:592-600`
- wall-clock автосворачивание `_statsIdleMs` 30 с — `OverlayMachine.cs:311-318`
- `StatsLayout.StatsPillWidth` инфляция до 394px при клике

## Что меняется

- `IslandLayout.SizeFor` / `OverlayMachine.WidthFor` — для `SystemStats` возвращают **высоту 72** и фиксированную ширину ~300, а не инфлируют ширину по числу метрик
- `OverlayMachine` — SystemStats закрывается по `PointerLeave` (команда), а не по таймеру
- `OnPillHoverEnter` / `TickHoverPin` — при `Kind == Idle/Collapsed` открывают SystemStats вместо date-peek
- `OnStatsSnapshot` — новое форматирование сети, цвет по порогам
- `PlayClickPop` — подключить к клику по пилюле (пин/анпин)
- `OverlayTokens` — `StatsExpandedH = 72`, `StatsExpandedW = 300`, пороги акцента
- `docs/ISLAND_GUIDELINES.md` §3 — правило «высота всегда CollapsedH = 30» получает исключение для SystemStats
- `AppSettings` — `SystemStatsHoverPeek` (default true), `SystemStatsClickToOpen` удаляется

## Правило совместимости

Ничего из `feature/clipboard-cycle-pill` (цикл буфера обмена, шевроны, превью) не должно сломаться. `OverlayKind.Clipboard`, `CycleClipboardPrev/Next`, `HandleIdlePillClick` зоны ⅓/⅓/⅓ — без изменений.

## Дополнение — настройка строк монитора (1.12.1)

Повторный запрос пользователя (кастомизация поверхности монитора) реализован **сверху** этой переделки, отдельным изменением поверх неё. Панель перестала быть фиксированным набором из четырёх строк: пользователь выбирает, какие строки видны, и задаёт их порядок.

- Модель: NotifyIsland.Core/StatsLayout.cs — StatsRow (Cpu / Memory / Battery / Network / Date), StatsPreset (Brief / Full / Off / Custom), ResolveRows(preset, custom), StatsHeightFor(rowCount), StatsLayout.ShouldCollapseStatsSurface(...), LabelFor / NameFor / IsCaptionRow.
- Ключи: AppSettings.StatsRowsPreset (default Full) и AppSettings.StatsRows (упорядоченный список, default — все пять). Оба нормализуются в Normalize(), сериализуются читаемыми строками, не ординалами.
- UI: комбо пресета, редактор строк (чекбокс + ↑/↓, только для «Свой набора») и статичное превью на реальном StatsRowView с реальным StatsHeightFor.
- Вход: новый пункт ПКМ по пилюле «Настроить монитор…» открывает окно настроек на разделе «Монитор» (в т.ч. если окно уже видно).

### Два отклонения от наивного прочтения

1. **`Off` не предлагается в UI.** Значение есть в Core (StatsPreset.Off), но в комбо его нет: единственный выключатель — чекбокс «Показывать системный монитор». Причина — в одной панели не должно быть двух конкурирующих «выключить»; выключение монитора больше не трогает список строк пользователя.
2. **Превью в настройках статичное, а не live-значениями.** Оно переиспользует настоящий контрол StatsRowView и настоящий StatsHeightFor, поэтому расходиться с реальной пилюлей не может, но показывает мок-данные, а не текущие показатели системы — сознательно, чтобы превью не прыгало каждые 500 мс.
