# NotifyIsland 1.12.4 — слой анимации (таймлайны, easing, сниженная анимация)

Дата: 2026-09-29
Статус: реализуется
Предыдущая: 1.12.3 goo-шарик

## Почему не GSAP

GSAP — JavaScript-библиотека для DOM/SVG. Приложение нативное (Avalonia/.NET 8), JS-движка в
процессе нет. Единственный способ «подключить GSAP» — встроить WebView2 и рисовать остров в
HTML, что означало бы выбросить Core, FSM, настройки, трей и системные интеграции, уже
покрытые 342 тестами. Не делаем.

Идеи GSAP переносятся, а не библиотека: таймлайн вместо цепочки `delay`, именованные easing'и
как единый словарь, анимация трансформаций вместо `width`/`height`, обратимость
(`reverse` вместо набора частных случаев), режим сниженной анимации.

## Диагноз текущего состояния

1. **Анимируется раскладка.** `Pill.Width = w` каждый кадр → Avalonia пересчитывает дерево.
   Это же отмечено в скилле GSAP как антипаттерн.
2. **Нет таймлайна.** Фаза A (разъезд острова) и фаза B (отщепление шарика) связаны
   константой `BlobPeekShare`, которую надо синхронизировать вручную; тронул одну — разъедутся
   обе.
3. **Easing разбросан.** `CubicOut`, `ClickPop`, `AppearProgress`, `Ragged` живут в разных
   местах; общего словаря нет, настройки скорости — полуавтоматы.
4. **Нет сниженной анимации.**

## Слой

Всё чистое — в `NotifyIsland.Core`, без типов Avalonia, с тестами.

### `AnimEase` — словарь кривых

Именованные функции `double Ease(string name, double t)`, как у GSAP. Именованные кривые
GSAP-стиля, а не позиционный подбор:

- `linear`
- `power1.out` … `power4.out` / `.in` / `.inOut` (степень кубической/квадратичной/quart)
- `back.out(1.7)` — перелёт с отскоком
- `expo.out`, `circ.out`, `sine.inOut`
- `clickPop` — уже существующая кривая, переезжает в словарь, а не остаётся особняком
- `ragged` — существующая «рваная» посадка

Плюс `WithReducedMotion(ease, t, enabled)`: при включённой сниженной анимации — step-функция
в конце (t→1), чтобы элемент не «прыгал», а просто оказался в конечном состоянии.

### `AnimTimeline` — расписание сценария

```
new AnimTimeline(("peek", 0.00, 0.40), ("detach", 0.40, 0.70), ("travel", 0.70, 1.00))
```

- фазы объявлены одним списком, берут время из одного источника — разъехаться не могут;
- `PhaseAt(t)` возвращает фазу и локальный прогресс 0..1;
- `Reverse()`/`Progress(t)` — прерывание анимации становится обратимостью, а не
  `SettleBlob`/`ApplyBlobRest`;
- общая длительность = 1.0, реальные миллисекунды задаёт существующий `AnimationTiming`.

### `AnimReduced` — режим сниженной анимации

Глобальный флаг в `AppSettings` (`ReducedMotion`), выводимый из `SystemParameters.ClientAreaAnimation` (настройка ОС «Анимации в Windows»), плюс переключатель в существующей секции настроек анимации. При включении: длительность → 0, ease → step, бесконечные циклы (breathe шарика, пульс unread) — выключены. Это требование доступности, а не украшение.

## Миграция, по одной анимации за раз

Старое не выбрасывается целиком: каждая анимация переводится на таймлайн, пока не переведена
— она работает как раньше. Порядок (от того, что пользователь видит и жалуется, к фону):

1. **Сценарий копирования** — разъезд острова → отщепление → выезд шарика → верёвка.
2. **Морфы капсулы** — переходы размеров на трансформациях.
3. **Hover-peek** и монитор.
4. **Появление/исчезновение** (appear/dismiss, включая Ragged/Glitch).
5. **Таймер, медиа, unread-пульс.**

## Инварианты, которые нельзя сломать

- остров не двигается; верёвка неразрывна; drag клампится кругом 100 DIP;
- пустые области окна не перехватывают ввод;
- всё, что анимируется трансформациями, не должно вызывать пересчёт раскладки;
- сниженная анимация не «ускоряет», а убирает движение.

нашли по два бага, которых не видели ни тесты, ни ревью.
