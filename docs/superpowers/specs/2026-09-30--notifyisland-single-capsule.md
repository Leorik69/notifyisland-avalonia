# 1.13 — одна капсула, монитор вместо плашек

Статус: предложено · Автор: mavis · Ветка: `feature/system-monitor`

## Проблема

В `NotifyIsland.Core/OverlayMachine.cs:7-21` объявлено 13 значений `OverlayKind`:

```csharp
Idle, Collapsed, Expanded, Notification, Progress, Media,
Timer, Error, Weather, Battery, Clipboard, SystemStats
```

Каждое из них **захватывает капсулу целиком**. Одна плашка может одновременно показать
только один источник, и конкуренция за слот выглядит как россыпь: зарядка, плеер, таймер
и прогресс вытесняют друг друга на 3.5–4000 мс (`BatteryAlertLogic.cs:15`,
`OverlayTokens.cs:23`), причём `Media` и `Timer` ещё и вечные (`_notifyMs = 0`,
`OverlayMachine.cs:220`).

При этом система строк монитора (`StatsRow` в `StatsLayout.cs:13-20`) — уже ровно та
абстракция, которая нужна: enum, произвольный набор и порядок в настройках, живой
предпросмотр, добавление вида не трогает редактор. Плеер и таймер — это не «плашки»,
это строки.

Реально `Notification` и `Error` существуют только в демо-режиме
(`OverlayMachine.cs:566`, `:571`): единственный боевой `Notify` — низкий заряд
(`OverlayWindow.axaml.cs:3230`). То есть перенос затрагивает четыре боевых пути,
а не тринадцать.

## Решение

Правило одно: **капсула — приборная панель, а не очередь плашек.**

1. Строка часов — всегда. Дата, погода, батарея живут в ней же чипами.
2. Нижняя полоса капсулы — прогресс активного процесса: копирование, воспроизведение.
3. Монитор поглощает всё остальное: плеер и таймер становятся строками `StatsRow`.
4. Перехват капсулы остаётся у низкого заряда.

### Решения пользователя

| Вопрос | Решение |
|---|---|
| Где полоса прогресса | Занимает нижнюю полосу вместо цифр секунд |
| Кнопки плеера на капсуле | Убрать; на капсуле только полоса, остальное — в мониторе |
| Что оставить перехватом | Только батарея и зарядка |

## Геометрия: почему высота не меняется

Внутри `Pill` уже есть нижняя полоса 8 DIP — `SecondsStrip`
(`OverlayWindow.axaml:324-332`, `Height="8"`, `VerticalAlignment="Bottom"`), и
`OverlayProgress` стоит в той же полосе (`OverlayWindow.axaml:334-341`, `Height="2"`).
Одновременно они не нужны: цифры секунд и прогресс конфликтуют по смыслу.

Полоса прогресса **вытесняет цифры секунд**, когда процесс активен. `CollapsedH = 30`
(`OverlayTokens.cs:18`) и вся производная геометрия остаются нетронутыми, миграция
не задевает ни один расчёт размера. Это ключевое условие спеки: если в ходе работы
понадобится изменить `CollapsedH`, значит полоса влезла не туда.

## Изменения

### Обязательные

**`NotifyIsland.Core/StatsLayout.cs`**
- `StatsRow` += `Media`, `Timer`.
- `NameFor` для новых строк; `LabelFor` («Плеер», «Таймер»).
- `BriefRows` без изменений (`Cpu` + `Battery`).

**`NotifyIsland.Core/OverlayMachine.cs`**
- `Notification`, `Progress`, `Media`, `Timer`, `Error` перестают захватывать капсулу:
  `Dispatch` переводит их в данные строк монитора, `_kind` остаётся `Idle`/`SystemStats`.
- `Tick` больше не уводит `_notifyMs` для этих видов.
- Демо-пути `DemoNext` сохраняются — на них держится `--demo` (F9).

**`OverlayWindow.axaml`**
- Нижняя полоса: `ProgressBand` вместо показа `SecondsStrip` при активном прогрессе.
- `MinimalBattery` остаётся в строке часов (пользователь на стационарном ПК, но
  строка не мешает и выключается сама при отсутствии батареи).

**`OverlayWindow.axaml.cs`**
- `ShowChargePill` — без изменений, это единственный оставшийся перехват.
- `ApplySmtcSnapshot` (`MediaControls`/обложка/`OverlayProgress`) → заполнение строки
  `Media`; кнопки переезжают в `StatsRowView` строки плеера.
- `StartCountdownMinutes` / `StartStopwatchFromSettings` → заполнение строки `Timer`.
- `Paint`: `OverlayProgress` виден только при активном прогрессе, `SecondsStrip` — иначе.

**`StatsRowView.axaml(.cs)`**
- Новая форма строки: действие справа (`⏮ ▶ ⏭` для плеера, `⏸ +1 ✕` для таймера).
- Высота строки с действиями считается по тем же 16 DIP, если кнопки помещаются.

**`WindowsMediaSessionSource.cs`**
- Позиция и длительность уже опрашиваются (`:250-260`, раз в секунду) и отдаются
  нормированной долей. Для строки плеера этого достаточно; абсолютные mm:ss
  понадобятся только если решит пользователь — тогда добавить два поля в снапшот.

### Вероятные

- `NotifyIsland.Core/OverlayTokens.cs` — только если новая строка не укладывается в 16 DIP.
- `SettingsWindow.axaml(.cs)` — в списке строк появятся «Плеер» и «Таймер» автоматически
  (редактор enum-driven), возможно нужен текст подсказки.
- `IslandTimerLogic.cs` — перевод состояния таймера в строку.

### Не трогаем

`CapsuleMorphTrack`, `AnimEase/AnimTimeline/AnimReduced`, `ClipboardBlob`,
`ClipboardHistoryPanel`, `IslandLayout` (кроме возможной проверки), `CapsuleMorphTrackTests`.

## Риски

- **Плеер перестаёт быть виден без наведения.** Компромисс пользователя; полоса
  прогресса на капсуле частично компенсирует — идёт музыка, значит полоса ползёт.
- **Таймер без перехвата можно пропустить.** Компенсация — та же полоса прогресса:
  оставшееся время показывается полосой, а строка монитора даёт цифры.
- **Три полосы в одной 30 DIP капсуле.** Полоска одна; приоритет: копирование,
  воспроизведение, таймер. Проигравшие остаются строками монитора.

## Критерий готовности

- [ ] Полоса прогресса появляется на капсуле при копировании и воспроизведении,
      вытесняя цифры секунд, без изменения высоты окна.
- [ ] Плеер и таймер видны в строках монитора, кнопки в них работают.
- [ ] Клавиатурный прогон `NotifyIsland.Tests` зелёный, легенда обновлена.
- [ ] Живой прогон: окно не меняет высоту ни при каких событиях.
